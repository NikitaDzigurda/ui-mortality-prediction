# Сосудистые исходы — локальное приложение

PySide6, без сервера и сетевой передачи данных. Python 3.11–3.12.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Откройте подготовленную таблицу CSV (разделитель определяется автоматически) или первый лист XLS/XLSX. Для дополнительного исследования подходит `Госпитальные_исходы/01_данные.csv`. Клинические данные в репозиторий не включены. Сырые даты и текстовые исходы предварительно нужно привести к бинарным 0/1. Неизвестный исход исключается с указанием числа строк. Пропуски предикторов не считаются отрицательными значениями.

Выберите исход и его положительный код, идентификатор пациента, столбец бассейна и группу. Отключайте признаки флажками; в третьей колонке можно задавать категориальный тип. Идентификаторы и исход нельзя включать в предикторы. Предварительно выбраны 14 признаков дополнительного исследования. Любые другие признаки требуют явного включения пользователем, включая проверку доступности до исхода.

Программа показывает классическую статистику с FDR, внешние OOF-метрики, ROC/PR, матрицу ошибок, перестановочную важность на внешних блоках. Гиперпараметры RF/LR подбираются Optuna TPE внутри train; импутация, масштабирование и кодирование также обучаются внутри train. Порог выбирается по внутренним OOF, внешние исходы в выборе не участвуют. Отмена доступна в верхнем меню во время расчёта. Экспорт создаёт отдельную папку с протоколом, тремя CSV и графиком.

## Связь с исследованием

Изучены `01_данные_и_подготовка.ipynb`, `02_модели_Optuna_и_эксперименты.ipynb`, отчёт и `02_реальные_final_config.json`. Заимствованы признаки, seed 2026, групповые разбиения, основной критерий AP и пространства поиска LR/RF. Приложение реализует отдельную ветвь all_real. В исходном исследовании также были сокращение выживших 1:10/1:5, поправка вероятностей, CatBoost/XGBoost и три повторения внешнего CV; здесь они не реализованы. Сохранённые параметры полной выборки не переиспользуются как будто это независимая оценка. Важность здесь permutation importance, не SHAP. Автоматического удаления по p-value нет: набор выбирается до вложенного обучения.

## Ограничения

При недостатке событий в train/test приложение прекращает расчёт с объяснением. Статистические проверки описательные, повторные записи в них не учитываются; ML разделяет пациентов по ID. FDR относится к выбранным факторам текущей группы, а не всем запускам приложения. Важность не является причинным эффектом. Подбор набора по многим внешним оценкам требует последующей независимой проверки. Эта программа не является клиническим калькулятором.

## План реализации

1. Загрузка и явная настройка ролей столбцов.
2. Выбор бассейна и набора факторов.
3. Классическая статистика и вложенный RF/LR + Optuna.
4. Графики, объяснение протокола, локальный экспорт.

Эти этапы реализованы. Дальнейшие отдельные расширения: повторения CV, SHAP, оставшиеся семейства и ветви сокращения из оригинального эксперимента, адаптер сырых анкет с явным сопоставлением столбцов.
